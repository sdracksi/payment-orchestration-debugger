# Release v0.3.0 - Transactions API

## Objective

Build the first production-ready Transactions API for the Payment Orchestration Debugger.

This API will expose transaction data for the future React frontend and support filtering, pagination, and JSON serialization.

---

## API Design

### Endpoint

GET /api/v1/transactions

### Purpose

Returns a paginated list of payment transactions.

This endpoint will be consumed by the React frontend dashboard to display transaction activity.

### Response Format

Content-Type: application/json

### Initial Version

The first implementation will return all transactions ordered by the most recently processed transaction.

Filtering and pagination will be added incrementally during this release.

## Response Contract

Each transaction will be returned in the following format.

```json
{
  "id": 1,
  "transaction_reference": "txn_310297294b1e090b",
  "merchant_reference": "ORD-361850",
  "merchant_name": "Checkers",
  "gateway": "cybersource",
  "amount": 947.87,
  "currency": "GBP",
  "status": "failed",
  "payment_method": "paypal",
  "latency_ms": 887,
  "processed_at": "2026-07-23T08:03:49Z"
}
```

## Scope

### Endpoints

- GET /api/v1/transactions
- GET /api/v1/transactions/:id

### Features

- Transaction listing
- Transaction details
- Filtering
  - Status
  - Gateway
  - Merchant
- Pagination
- JSON serialization
- Request specs
- Seed data

---

## Out of Scope

- Authentication
- Authorization
- Creating transactions
- Updating transactions
- Deleting transactions

These will be implemented in future releases.

## Controller Design

### TransactionsController

Responsibilities:

- Receive HTTP requests
- Query transactions
- Return JSON responses
- Handle filtering
- Handle pagination

The controller will not contain business logic.

Business logic belongs in the domain layer as the project grows.
